# Contributing

Current contributions are requirements, research, threat modeling, contract review and synthetic acceptance scenarios. Do not add application code or UI designs until the corresponding phase is authorized.

Discuss substantive changes in an issue; include the user problem, evidence, alternatives, acceptance conditions and risks. Clearly distinguish observations from proposals. Use original work or compatible licensed material with provenance. Do not include proprietary vendor code, logos, licensed terminology datasets or patient information.

Use Developer Certificate of Origin sign-off (`git commit -s`) for future contributions: contributors certify the right to submit their work under the repository license. No copyright assignment is requested. See https://developercertificate.org/ for the full DCO.

Clinical workflow and financial correctness changes need review by the relevant professional as well as engineering review. Security fixes should follow SECURITY.md. Maintain a useful exit/export path and API parity as features develop.
